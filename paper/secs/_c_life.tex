\subsection{Persistent-memory lifecycle: specified only}
Nothing implemented/measured.

Stable handles outlive blocks. \textsc{Rebind}$(h, b')$ repoints $h$ to $b'$, bumping per-handle version; readers see old/new target, never torn mix. \textsc{Forget}$(h)$ tombstones: handle persists, \textsc{Deref}$(h)$ fails closed, never stale text. \textsc{Alias}$(h)$ adds refcounted second handle, independent version chain, so one alias rebinds/forgets without affecting other. \textsc{Deref}$(h)$ resolves current target or raises tombstone. Dereference version checks let builder detect concurrent rebinds and retry.

Edit stress: 100 sequential swaps/contradiction injections over fixed set, CPU-only. Metrics: stale-answer rate and ms/edit (repoint plus re-embedding). Bar: $<5\%$ stale, sublinear ms/edit growth in stored blocks. Not run.

RAG upsert has no stable handle: identity is embedding, so edits churn index and invalidation rests on re-embedding plus heuristics admitting stale hits \cite{chhikara2025mem0}. Temporal-graph versions facts at per-edit graph cost \cite{rasmussen2025zep}. LLMLingua-style compression recompresses edited regions. Specified pointers isolate mutation to one handle plus version bump, leaving others untouched.
