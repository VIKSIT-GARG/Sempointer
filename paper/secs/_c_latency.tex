\subsection{Prefill compute-bound, decode memory-bound}
Full self-attention costs $O(L^2 d)$ prefill for length $L$, width $d$~\cite{vaswani2017attention}: every query scores every key---compute-bound on CPU. Autoregressive decode moves full key-value state for $L$ positions, costing $O(Ld)$ traffic/token---bandwidth-bound. Separate phases for latency claims.

\subsection{TTFT vs TPOT}
Time to first token (TTFT) is prefill over the fused prompt. Time per output token (TPOT) is decode bandwidth on installed state. Smaller fused $L$ cuts both: fewer prefill FLOPs, fewer bytes/decode step.

\subsection{Why FLOPs-only $K^\ast$ is necessary but insufficient}
Let $K^\ast$ be breakeven selected-token count where reader attention FLOPs equal full-context prefill FLOPs plus selection overhead. $K < K^\ast$ is necessary for prefill FLOPs win, insufficient end-to-end: (i) selection, encoding, fuse add CPU fixed costs outside FLOP count, (ii) TPOT tracks bytes moved, not FLOPs. Clearing $K^\ast$ can still lose wall-clock when overhead beats saved attention or decode streams large state.

\subsection{Two cost centers: $M_{\mathrm{text}}$ vs $M_{\mathrm{kv}}$}
$M_{\mathrm{text}}$ stores verbatim block text and fuses selected blocks into the prompt, re-prefilling per query. $M_{\mathrm{kv}}$ stores block key-values, pages them into decoder, in the spirit of paged management~\cite{kwon2023pagedattention}, trading re-encode for per-step paging traffic. This concept paper uses $M_{\mathrm{text}}$ only; $M_{\mathrm{kv}}$ is the opposite-bottleneck alternative.

\subsection{Prefix-cache compatibility}
A stable pointer table yields a reusable prefix: unchanged blocks keep identical codes, so a recurring shortlist gives a byte-identical fused prefix that a standard KV prefix cache skips. Stability enables hits, not speedup by itself.
